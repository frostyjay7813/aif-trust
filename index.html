The Problem

Your AI Agents Are a Black Box — And That's a Liability

When auditors ask "what did your agent do?", logs aren't enough. You need cryptographic proof. The emerging category — Daylite, ProofAgent, Lineation, and others — validates the demand. AIF Trust delivers the integrated stack.

No Audit Trail

Agent actions produce logs, not evidence. Logs can be modified. There's no cryptographic proof of what happened, when, or under whose authority.

No Trust Signal

When an agent succeeds 100 times, does that mean it's trustworthy? Or lucky? Without provenance, you can't distinguish reliability from coincidence.

No Replay Capability

When something goes wrong — and it will — you can't reconstruct the exact execution context. Root cause analysis becomes guesswork.

No Governance

Who decides what agents are allowed to do? Under what conditions? Without policy gates, every agent operates with implicit trust — until it doesn't.

Platform

The Trust Infrastructure Layer

Four production-hardened subsystems that make autonomous execution provable, auditable, and governable.

🔏

Execution Receipts

Every agent action produces a sealed receipt — mission context, authorization snapshot, execution metrics, artifact hashes, and evidence bundle. SHA-256 sealed at creation. Immutable append-only ledger.

🕸️

Provenance Graph

10 node types, 8 relationship types. Trace the full lineage: mission → strategy → artifact → execution → receipt → evidence → verification → approval → promotion. Every node reachable from origin.

🔄

Replay Engine

Deterministic reconstruction of any past execution from sealed receipts. Compare across 4 dimensions: context hash, status, tools, artifacts. Verdict: MATCH, DRIFT, DIVERGENCE, or ERROR.

⚖️

Authorization Gate

Six-check pipeline: agent permission → cost limits → policy evaluation → sandbox requirements → approval gates → audit trail. Every decision produces an audit entry. Unknown agents default-allow in dev, default-deny in production.

📊

Observability Pipeline

Metrics derived from receipts, not separate instrumentation. Receipt metrics, provenance metrics, replay metrics, SLO tracking. Operators see what happened; auditors see the proof.

🔐

Policy Governance

Configurable policies: minimum trust score, maximum risk tolerance, required approval gates. Versioned policy snapshots preserved with every execution. Policy engine (hard rules) + reasoning engine (judgment) operate independently.

Questions

Frequently Asked

For technical decision-makers evaluating agent governance.

How is this different from logging?

Logs are descriptive ("agent called tool X"). Receipts are evidentiary — sealed with content hashes, carrying authorization context, and forming an immutable append-only ledger. Logs can be modified; receipts cannot be altered without detection.

What does the replay engine actually verify?

It reconstructs execution context from sealed receipts and compares across four dimensions: context hash (exact match required), execution status, tools invoked, and artifacts produced. The verdict is MATCH, DRIFT, DIVERGENCE, or ERROR — not a fuzzy score.

How does authorization work?

Six independent checks run before any agent action: agent permission verification → cost limit enforcement → policy evaluation → sandbox requirements → approval gates → audit trail creation. Each check is isolated. Unknown agents default-allow in development, default-deny in production.

Can AIF Trust integrate with existing CI/CD?

Yes. Execution receipts are JSON-serializable and can be exported to any observability stack. The provenance graph can be queried via API. The replay engine runs as a standalone service. All components are designed for integration.

What technology stack does it run on?

Python 3.11+ runtime with PostgreSQL (Supabase) for persistence. Plugin architecture for Hermes Agent. Event-sourced with CQRS patterns. Command bus, event store, and adapter layer for provider integration. Open-core model.

Is this SOC 2 / GDPR compliant?

The architecture supports compliance — immutable audit trails, policy-enforced data handling, and cryptographic proof of processing. Certification roadmap: SOC 2 Type II target Q1 2027. Contact Enterprise for details.
